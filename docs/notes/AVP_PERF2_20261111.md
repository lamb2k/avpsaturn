### Design as built (deviations from the answer in bold)

- **Master** (`snap_layer`, scroll 1 only): the copy pass ORs the xor of each new word with the word it replaces into one accumulator per row, builds the mask last, and stores `s1_rows`, `s1_from` (the sum before the copy) and `s1_seed`. A changed seed (position, `hud_flush`, `sel_ok`) sets every bit. Exact compare, no hash. **The first version shifted by the row inside the loop and cost +520 ticks of snapshot on a changed frame (the SH-2 has no variable shift); the accumulator form costs about +340 over the plain copy (section 4).** Four columns are walked at a time so the old words of a row share a cache line.
- **Slave eligibility** (`s1d_begin`): `drawn_valid`, `snap.s1_from == drawn_s1`, same position, `home`, `hud_flush`, `sel_ok` as the last scroll 1 draw, no menu, no character select, no refused lookup in the last scroll 1 draw (the blank mask pass's refusals are counted too: `s1_bm_refused`), mask not all ones. Anything else takes the full path.
- **Plan** (`s1_dirty_plan`): re-stamp first (every visible row that is neither changed nor blank for good: its 45 names, slot = character number - 0xC00, stamp set to the current one, `used` counted), then widen: each changed row and the runs of rows that are not fully droppable touching it above and below, judged on the new words, with the blank mask computed lazily only for the rows the runs touch.
- **Draw**: the existing row loop and cell code, skipping rows outside the plan.
- Snapshot grows by 12 bytes (`s1_rows`, `s1_from`, `s1_seed`): `lw_free` unchanged (96, the structure's alignment absorbs it).

## 2. Exactness evidence

HOST, `tests/host_gfx_s1_dirty.sh` (new; built on `host_gfx_s1_identity.c`): reference = same build without the switch. Per frame, hash A = the resolved scroll 1 layer (every visible name followed to its 8x8 cell contents, bank and flips) and hash B = VDP1 VRAM, CRAM, registers and VDP2 VRAM outside scroll 1's name table and cell slab. VDP2 VRAM itself is not byte identical (a full redraw may evict and re-upload a tile; the incremental one cannot), so the old VRAM hash cannot be used. Generator: single cell edits in HUD rows, rows cleared to a blank word or set to one tile, runs of repeated tiles (fully droppable rows that hold tiles), 2 to 4 row banners joining and splitting blocks, the story box rows (weights path), position moves and sub-cell moves, play flag / character select flags toggling, scroll 1 off for a quarter of the frames, new-screen bursts from tile pools (pack of 700 and of 1,800 keys against 764 slots: evictions) and pools of 760 codes (more distinct tiles than slots: refusals). Also the two-thread mode with the layer wait raised (a torn layer half would change a hash). The in-draw verify pass runs on every incremental draw.
Result at this head (3,000 frames a run, 6 seeds, WSL gcc): all 24 runs identical on every compared frame (hash A and hash B), sequential and two-thread, packs of 700 and of 1,800 keys.

## 5. Readout peak row

`DRAW n PEAK n` on row 26 (the third line under `PIC/GAME` and `MISS/SKIP/HELD`): DRAW = the longest slave picture (wake to return of `sat_gfx_draw`) in the last second, PEAK = the longest since the game's stage word last changed, in slave ticks (4.76 microseconds). Hot side: one compare and store per picture in the slave loop (`sat_fps_dmax`, 4 bytes in the cart image); the cold side reads and clears it once a second. Hot side: a compare and a store (not counted separately in the build report). Capture (EMULATOR, stage 0e, disc `PD2`, 440 vblanks in): `E:\AvP\learning\lane-perf2\hud_PD2_0e.png` reads `PIC 58 GAME 60 / MISS 0 SKIP 1 HELD 0 / DRAW 3315 PEAK 7750`. The numbers print to 99,999 (a stage first frame of 42 K fits).
